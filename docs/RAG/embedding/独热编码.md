# 独热编码（One-Hot Encoding）

## 定义

- 独热编码把一个有 k 个互斥类别的分类变量映射为 k 维二元向量，向量中只有对应类别位置为 1，其余为 0。
- 数学上，对于类别集合 {c1, …, ck}，类别 ci 对应标准基向量 ei（第 i 个分量为 1，其余为 0）。

## 示例

- 类别集合：`红, 绿, 蓝`
  - `红` → [1, 0, 0]
  - `绿` → [0, 1, 0]
  - `蓝` → [0, 0, 1]

## n 维与 2^n 的关系

- 结论：是否能表示 2^n 个状态取决于编码规则。

- 独热编码（one-hot）：n 维只能表示 n 个互斥类别（向量中恰有一个 1），因此不是 2^n。

- 二进制/位向量编码：若允许任意 0/1 组合，n 位可表示 2^n 个不同状态（从全零到全一）。

- 举例（n=3）：
  - one-hot：可表示 3 类（[1,0,0]、[0,1,0]、[0,0,1]）。
  - 二进制任意组合：可表示 8 种状态（000、001、010、011、100、101、110、111）。

- 选择建议：若类别是互斥且无序，使用 one-hot 能更清晰表达类别语义；若需要用更少维度编码大量状态，可考虑二进制编码、哈希编码或学习嵌入，但要注意二进制编码可能引入顺序性或相似性暗示。

## 为什么通常不用二进制编码

- 引入顺序/相似性假设：二进制位的组合会在数值或位相似性上隐含关系，误导模型把“位接近”当成“类别接近”。
- 干扰线性/距离模型：线性回归、逻辑回归、KNN 等模型会把位的数值或汉明距离当作有意义信号，导致错误的关系学习。
- 可解释性差：one-hot 的每一列映射到单一类别，权重直观；二进制位混合多个类别，模型权重难以解释。
- 学习难度增加：模型需从位组合中辨识出互斥类别，训练更难、样本需求可能增加，且更易出现欠拟合或错误归类。
- 较低的稳健性：在类别非常不均衡或噪声数据下，二进制编码更容易放大错误影响。

- 何时可接受：当极端节省维度是硬性需求且能接受引入顺序性假设时，可权衡使用二进制或哈希编码；更推荐使用哈希编码、目标编码或学习嵌入作为替代方案。

## 常见实现

- pandas:

```python
import pandas as pd
df = pd.DataFrame({'color': ['红','绿','蓝','红']})
pd.get_dummies(df['color'], prefix='color', drop_first=False)
```

- scikit-learn:

```python
from sklearn.preprocessing import OneHotEncoder
enc = OneHotEncoder(sparse=False, handle_unknown='ignore')
X = [['红'], ['绿'], ['蓝'], ['红']]
X_enc = enc.fit_transform(X)
```

## 优点

- 能把无序类别转为数值形式，避免错误地引入顺序关系。
- 与线性模型、距离度量方法等兼容，结果可直接用于大多数机器学习算法。

## 缺点与注意点

- 维度爆炸：类别数较大时会产生高维稀疏矩阵，影响内存与计算效率。可考虑稀疏表示、降维或嵌入（embedding）。
- 虚拟变量陷阱（Dummy Variable Trap）：在某些线性模型中需丢弃一个哑变量（或使用 `drop_first=True`）以避免多重共线性。
- 对于支持原生类别的树模型（如某些实现的决策树、随机森林、LightGBM 的类别特征支持），不一定必须先独热编码。

## 替代方法

- 标签编码（Label Encoding）：将类别映射为整数，适用于有序类别或部分树模型场景，但会引入顺序假设。
- 目标编码/频率编码：在类别非常多时可降低维度，但要注意训练/测试泄露与正则化。
- 类别嵌入（Embeddings）：深度学习中常用，可在低维连续空间表示类别之间的相似性，适合大类别数场景。

## 实践建议

- 小类别数量（<几十）：使用独热编码简单且可靠。
- 中/大类别数量（数百到数万）：考虑频率编码、目标编码或学习嵌入；若仍用独热编码应使用稀疏矩阵并注意内存。
- 线性模型：记得处理虚拟变量陷阱（丢弃一列）。
- 跨验证与泄露：使用目标编码等有信息泄露风险的方法时，在交叉验证/训练流程中确保正确的折内拟合与平滑策略。
