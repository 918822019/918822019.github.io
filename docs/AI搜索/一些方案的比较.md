# 起点AI搜书

## 背景

通过人工智能（AI）结合用户提问，返回符合用户查询（query）的书籍。用户可以直接点击链接查看，同时返回推荐该书籍的理由。

## 模型

所使用的模型为Deepseek-r1，未使用混元（Hunyuan）的原因不明，推测可能是由于模型能力不足。

在查询（query）进入模型之前，会进行预处理，进行一次过滤，将一些不相关的查询过滤掉，但模型效果较差。

示例：

```python
query:你好
这个查询会被过滤掉
query:你是什么模型
这个查询会被路由到搜索模型、模拟器、建模相关的小说。
```

## 数据召回

数据召回的具体方式不明确，可能是基于RAG或参考Claude代码，通过代理（agent）自行搜索并总结获取数据。

由于响应速度较快，推测可能是通过RAG召回实现的，否则通过代理自行搜索和总结的结果会较慢。

根据其思考过程反推，RAG召回可能经过以下步骤：

1. 对小说进行embedding处理，并生成摘要。
2. 使用书籍标签进行多路召回。
3. 是否通过提取关键词进行精确搜索作为召回路径之一尚存疑。

可以通过测试输入查询验证，通常需要等待3-5秒左右。

推测流程为：查询改写 + RAG召回。

随后，大语言模型（LLM）会处理其思考过程，生成多个作品，进一步验证数据是通过RAG召回后注入到提示（prompt）中，再由LLM推理选择。

## 输出

输出结果包括书籍名称、作者、简介、推荐理由，用户可点击链接直接跳转至起点查看书籍。

## 总结

该场景与我们的场景有一定相似性，均涉及一定数量且相对稳定的产品（如小说的更新速度在起点较低，因为起点对AI书籍的管控较严格）。

此外，存在一些共性，例如：

- 小说可能需要标签：玄幻、大作家、连载等。
- 基金或股票中同样存在标签：大私募/公募、稳定、高收益等。
