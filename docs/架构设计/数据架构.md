# 数据架构

本文档描述本仓库的集中式数据管理架构设计。

## 设计原则

```
每个项目只包含代码，不包含数据。
数据统一存放在 data/ 目录下，通过相对路径引用。
```

## ModelScope 上传管理

### 概述

爬取的书籍数据通过 ModelScope 数据集仓库 [wzywuan/Novel-Collection](https://modelscope.cn/datasets/wzywuan/Novel-Collection) 做云端备份与分发。

上传的数据分为两部分：

| 内容 | 本地路径 | 上传策略 |
|------|----------|----------|
| 完整数据库 | `data/book_search/books.db` | 全量上传（首次），后续覆盖 |
| 分片数据 | `data/book_search/shards/` | 增量上传（推荐），只传变化的分片 |

### 分片系统

为避免每次上传 57GB+ 的完整数据库，系统将 10000 本书拆分为 **50 个分片**（每个分片 200 本书），支持增量更新：

```
data/book_search/shards/
├── index.json              # 分片索引（覆盖率统计）
├── books_000001_000200.db  # 分片 1
├── books_000201_000400.db  # 分片 2
├── books_000401_000600.db  # 分片 3
├── ...
└── books_098001_010000.db  # 分片 50
```

`index.json` 记录每个分片的正文覆盖率，用于巡检哪些分片还在补抓。

### 增量上传机制

增量上传通过**本地 manifest 文件**追踪已上传的文件状态：

```
# manifest 文件位置（自动生成）
data/book_search/.book_search.modelscope-upload-manifest.json
```

**工作流程：**

```
1. collect_folder_state()  遍历 data/book_search/shards/
    │                         对每个文件计算 sha256 + 大小
    ▼
2. load_manifest()          读取上次的 manifest 文件
    │
    ▼
3. diff_folder_state()      比较：当前 sha256 ≠ manifest 中的 sha256
    │                          → 加入 changed_files 列表
    │                       远端有但本地无 → 加入 removed_files（仅提示，不自动删除）
    ▼
4. upload_file()            逐个上传 changed_files 到 ModelScope
    │                         每个文件独立 commit
    ▼
5. save_manifest()          将当前文件状态写入 manifest
```

**关键安全特性：**

- **SQLite 一致性快照**：上传 `.db` 文件时，如果检测到 WAL/SHM 伴随文件（表示数据库正在写入），自动通过 `sqlite3.backup()` 创建一致性快照再上传，避免上传损坏的数据库。
- **SHA256 内容寻址**：基于文件内容的哈希值而非修改时间判断变化，避免时间戳漂移导致误传。
- **断点续传**：每次单个文件上传成功后才会继续下一个，中途中断不会丢失已上传部分。
- **Dry-Run 预览**：`--dry-run` 模式只打印会上传的文件列表，不实际执行。

### SQLite 上传安全模式

```
--sqlite-snapshot auto    # 默认：检测到 WAL/SHM 时自动创建快照
--sqlite-snapshot always  # 强制所有 .db 都创建快照再上传
--sqlite-snapshot never   # 直接上传原始文件（不推荐）
```

在 `auto` 模式下，只有当 `.db` 文件存在对应的 `-wal` 或 `-shm` 文件时才会创建快照。

### 注意事项

1. **不会自动删除远端文件**：如果本地删除了某个分片，远端不会自动删除，需要手动在 ModelScope 控制台操作。
2. **WAL 模式检测**：如果使用 SQLite WAL 模式，脚本会检测到 WAL 文件并自动创建快照，上传速度会略慢但更安全。
3. **分片大小**：当前每个分片约 200 本书，可根据需要调整 `export_shards.py` 中的 `shard_size`。
4. **网络中断**：增量上传的断点续传基于逐个文件的粒度，如果网络中断，已上传的文件不会重复上传。

## 爬虫断点续爬

### 问题背景

每次爬取都需要遍历整个 `[start, end]` 范围，即使 99% 已完成，也要扫描所有 book_id 来判断哪些已爬。数据不全时无法直接开始使用，必须等全量数据就绪。

### 解决方案

爬虫引擎 `engine.py` 新增三个机制：

| 机制 | 参数 | 说明 |
|------|------|------|
| **自动续爬** | `--auto-continue` | 从上次中断的 book_id+1 继续，优先读取检查点，其次 DB 进度 |
| **定期检查点** | `--checkpoint-every N` | 每处理 N 本书保存一次位置到 `crawl_checkpoints` 表 |
| **信号处理** | (自动) | Ctrl+C 优雅保存检查点后退出，再按一次强制退出 |

**检查点表结构**（自动创建在 books.db 中）：

```
crawl_checkpoints
├── command      TEXT  PRIMARY KEY  -- "crawl-books" / "crawl-content"
├── range_start  INTEGER            -- 本次任务的 start
├── range_end    INTEGER            -- 本次任务的 end
├── last_id      INTEGER            -- 最后完成的位置
└── updated_at   TEXT               -- 更新时间
```

### 日常爬取工作流

```powershell
cd project/book_search

# 1. 首次运行（book 1-10000，每 100 本保存一次检查点）
python -m src.crawler.engine crawl-books --start 1 --end 10000 --auto-continue --checkpoint-every 100

# 2. Ctrl+C 中断后重跑 — 自动从断点继续
python -m src.crawler.engine crawl-books --start 1 --end 10000 --auto-continue

# 3. 正文爬取同样支持
python -m src.crawler.engine crawl-content --start 1 --end 10000 --auto-continue --checkpoint-every 100

# 4. sync-all 合并命令
python -m src.crawler.engine sync-all --start 1 --end 10000 --auto-continue
```

**注意**：检查点按 `(command, range_start, range_end)` 作为唯一 key。同一个 (command, range) 的检查点会自动覆盖。任务正常完成后自动清除检查点。

## 远程直读工具

### 问题背景

完整 `books.db` 约 57GB，每次从 ModelScope 全量下载耗时极长。更常见的是：
- 只想获取某个 shard 的数据
- 先拉取少量数据就开始爬取，边爬边补
- 在远程查一下有哪些文件，不需要下载

### modelscope_reader.py

提供四种操作模式：

| 命令 | 功能 | 示例 |
|------|------|------|
| `list` | 列出远程仓库文件（无需下载） | `py scripts/data/modelscope_reader.py list` |
| `pull` | 下载指定文件（HTTP Range 断点续传） | `py ... pull --file books_000001_000200.db` |
| `import` | 从远程 shard 合并数据到本地 books.db | `py ... import --remote-shard books_000001_000200.db` |
| `bootstrap` | 初始化：index.json + 可选 shard + 可选空 DB | `py ... bootstrap --shards 3 --create-db` |

**断点续传机制**（pull 命令）：
```
1. 检查本地已下载的文件大小
2. 发送 HTTP Range 请求头: Range: bytes={downloaded}-
3. 服务器返回 206 Partial Content
4. 从断点处追加写入本地文件
```

**Bootstrap 工作流（推荐新手使用）**：

```powershell
# 只需 index.json + 前 3 个 shard + 空 books.db（不下载 57GB 完整 DB）
py scripts/data/modelscope_reader.py bootstrap --shards 3 --create-db

# 然后直接启动爬虫，缺的数据爬取时会自动填充
cd project/book_search
python -m src.crawler.engine crawl-books --start 1 --end 10000 --auto-continue
```

**远程文件列表**（2026-07-04 数据）：

| 文件类型 | 数量 | 说明 |
|---------|------|------|
| `books.db` | 1 | 完整数据库（54.0GB） |
| `books_000001_000200.db` ~ `books_009801_010000.db` | 50 | 分片数据库（前 10 个 ~1.6-3.9GB，其余 ~20MB-1.7GB） |
| `shards/index.json` | 1 | 分片索引 |
| `books.json` | 1 | 书单元数据 |
| `.msc` | 1 | ModelScope 自动生成 |
