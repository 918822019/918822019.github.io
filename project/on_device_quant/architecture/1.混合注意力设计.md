# 混合注意力设计：DSv4 架构 + Linear Attention

> 本文档分析 DeepSeek-V4 混合注意力的结构，并提出"压缩前端 + Linear attention"的端侧改造方案。

---

## 1 问题回顾：视频级上下文的 KV Cache 爆炸

### 场景参数

| 量 | 值 |
|---|---|
| 视频时长 | 100 小时 |
| 抽帧帧率 | 1 fps |
| 每帧编码 tokens | 64 |
| 总 tokens | **23,040,000** |

### 标准 Attention 的 KV Cache（7B, 32 层, FP16）

| Attention 类型 | 单位 token 开销 | 23M tokens |
|---|---|---|
| MHA（32 heads） | 512 KB | 11.5 TB ❌ |
| GQA（4 heads） | 64 KB | 1.4 TB ❌ |
| MLA（rank=512） | 40 KB | 880 GB ❌ |

**结论：任何随序列增长的 KV cache 都不可行，必须常数级。**

---

## 2 DeepSeek-V4 混合注意力拆解

DSv4 的核心思想是**结构化压缩**，把长序列组织成三层金字塔：

```
原始序列 (n tokens)
    │
    ├── CSA 压缩 (m=4, 重叠) → n/4 个 compressed entries
    │     └── Lightning Indexer → top-k 个（Flash: 512, Pro: 1024）
    │
    ├── HCA 压缩 (m'=128, 不重叠) → n/128 个 compressed entries
    │     └── Dense attention 全量访问
    │
    └── SWA (窗口=128, 不压缩) → 保局部精度
```

### 各层的意义

| 层 | 压缩比 | 输出数量 (23M tokens) | 语义层级 |
|---|---|---|---|
| HCA | 128:1 | ~180K | **场景级**：每 128 帧（~2分钟）一个场景描述 |
| CSA | 4:1 → top-k | 512 或 1024 | **聚焦级**：当前最相关的细节 |
| SWA | 1:1 | 128 | **时间级**：最近 2 秒的精确帧 |

### DSv4 的瓶颈

压缩后的 KV cache 虽然大幅减少，但 **HCA + CSA 加起来仍有 O(L) 存储**：

```
L = 23M 时：
- HCA compressed KV: 23M / 128 × (head_dim × 组) ≈ 180K × (512 × 每组)
- CSA compressed KV: 23M / 4 × (head_dim × 组) ≈ 5.75M × (...)
- 加上 top-k 选择后的 cache，不是常数
```

DSv4 在 1M token 时 KV cache 是 V3.2 的 10%。这在云侧足够，在端侧 **100 小时视频仍会超出内存**。

## 3 改造方案：Linear Attention 替换压缩级 Attention

### 核心思路

DSv4 的压缩机制是一个很好的**结构化前端**，它把原始序列组织成有意义的时空层级。在此之上：

- **HCA compressed entries** → **Linear attention**（不存 KV，只维护 O(d²) 累积矩阵）
- **CSA compressed entries** → **Linear attention**（同上，指数衰减累积）
- **SWA uncompressed tokens** → **标准 Softmax attention**（保局部精度）

这样 KV cache 变成 **SWA 的常数 128×d**，不再随视频长度增长。

### 技术细节

#### HCA 路径（场景级覆盖）

```
输入: 每 128 帧压缩为 1 个 HCA entry C ∈ ℝ^c
原:  dense softmax on O(L/128) 个 entries → KV cache O(L)
改:  Linear attention:
       state = state + ϕ(C) ⊗ ϕ(C)   (累积外积矩阵, O(c²))
       output = Q · state / norm       (查询时一步读取)
```

- 累积矩阵大小：c=512 → 512×512 = **262K 参数**，恒定不变
- 180K 个 HCA entries 全部被"折叠"进一个矩阵中

#### CSA 路径（聚焦访问）

```
输入: 每 4 帧压缩为 1 个 CSA entry, 包含 2m 的重叠窗口
原:  Indexer 选 top-k, softmax on 选出的 k 个 items
改:  保留 Indexer（决定关注哪段）, 但不存 KV,
     用 Decaying Linear Attention 累积多级粒度
```

- Indexer 的 ReLU 打分机制本身就接近 linear attention 的特征映射
- Decaying 控制历史帧的关注程度：越早的帧权重越低

#### SWA 路径（局部精度保底）

```
不变: 标准 Softmax Attention, 窗口 128 tokens (~2秒)
      这是唯一需要存 KV cache 的部分:
      128 tokens × 层数 × head_dim × 2 = 常数内存
```

### 两阶段检索管道

**问题：Linear attention 丢失精确帧定位能力。**

**解法：Injest 和 Query 解耦。**

```
┌─────────────────────────────────────────────────────────┐
│ 阶段一：Ingestion（常驻运行，24/7）                       │
│                                                         │
│  视频流 → 抽帧 → Visual Encoder → CSA+HCA linear attn   │
│                                                         │
│  产出:                                                    │
│  - HCA 累积状态（O(c²) 常数） → "场景压缩摘要"            │
│  - 帧级 embedding → 写磁盘时序索引（按需）                 │
│  - CSA 的 decaying 状态 → "最近关注焦点"                   │
│  - SWA → "最近 2s 精确内容" → 实时处理                    │
│                                                         │
│  内存: 常数 ✓  不需 eviction ✓  无限运行 ✓                │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│ 阶段二：Query（用户触发）                                  │
│                                                         │
│  用户: "冰箱门什么时候打开的？"                             │
│                                                         │
│  1. Query 文本 → 编码 → Text Queries                     │
│  2. 对磁盘索引做 Cross-Attention（标准 MultiheadAttn）   │
│  3. 返回相关帧 + 时间戳                                    │
│                                                         │
│  精确性: 全量 Softmax Attention 在索引上 ✓                │
│  内存: 索引在磁盘，只需要加载 Top-K 结果 ✓                │
└─────────────────────────────────────────────────────────┘
```

## 4 与纯 Mamba / 纯 Linear Attention 的对比

| 维度 | 纯 Mamba | 纯 Linear Transformer | 本方案 (DSv4+Linear) |
|---|---|---|---|
| 长程检索 | ❌ 无 Attention，SSM 压缩丢失细节 | ❌ 特征平均化 | ✅ Indexer 保留结构化定位 |
| 局部精度 | ✅ 状态追踪 | ❌ 无局部窗口 | ✅ SWA（标准 Attention） |
| 常数内存 | ✅ | ✅ | ✅ |
| 可训练 | ✅ 稳定 | ❌ 训练不稳定（DMC 问题） | ✅ 分层结构分担优化难度 |
| 视频场景理解 | ⚠️ 每帧独立 SSM，无法交叉 | ⚠️ 模糊化 | ✅ 三层金字塔覆盖全尺度 |
| 推理速度 | ✅ 快速 | ✅ 快速 | ⚠️ 多一层压缩前处理 |
| 硬件兼容性 | ✅ 纯 GEMM | ✅ 纯 GEMM | ✅ GEMM + Indexer 顶稀疏 |

**本方案的独特价值：对视频场景的结构自觉性。**

纯 Mamba 把视频帧当成一个"很长的序列"均匀处理，丢失了"这是视频帧"的先验。DSv4 的压缩机制天然符合视频的时空结构（场景 → 片段 → 帧），用 linear attention 只是把存储复杂度问题解决掉，不破坏这个结构。

## 5 风险与权衡

### 5.1 索引器精度

CSA 的 Indexer 用 ReLU 打分做 top-k 选择 → 误选会漏掉关键帧

- **缓解**：HCA 路径 "cover all" 作为保底，即使 indexer 选错，HCA 的场景级累积不会漏掉事件
- **训练时**：Indexer loss + Attention loss 联合优化

### 5.2 Linear Attention 的退化

HCA 上的 linear attention 做全量累积，时间久了最近帧被历史淹没

- **缓解**：引入 Decaying factor（指数衰减，越早的帧权重越低）
- 用 SWA 承载最敏感的局部信息

### 5.3 磁盘索引 I/O

Query 阶段需要读盘做 cross-attention

- **缓解**：索引只存 embedding（~512 维），100h 视频约 180K × 512 × FP16 ≈ 180MB
- 可全量放进内存，不需要读盘
