## 1 硬件约束与设计原则

### 1.1 目标设备（家庭中枢）

| 指标 | 约束值 | 说明 |
|---|---|---|
| 功耗 | < 35W | 插电运行，散热有限 |
| 内存 | 24-48 GB | Mac Mini / NUC 级别 |
| 存储 | 512GB+ | 本地索引 + 模型 |
| 内存带宽 | ~200 GB/s | UMA（统一内存） |
| 推理时延 | < 2s | 非实时，可接受延迟 |
| 价格 | 7-8k RMB | 整机预算 |

### 1.2 训练设备（3060）

| 指标 | 值 |
|---|---|
| GPU | RTX 3060 12GB |
| 显存带宽 | 360 GB/s |
| FP16 Tensor Core | 127 TFLOPS |
| 混合精度 | 原生支持 |

### 1.3 设计原则

1. **硬件先于模型** — 每层设计时标注目标执行单元（CPU/NPU/DSP）
2. **量化内建** — 从定义层开始就带 scale/zero_point，不做事后 PTQ
3. **剪枝内建** — 每层自带可学习的 mask，训练时自动决定剪哪里
4. **无 HBM 假设** — 不假设内存无限快，显式管理 activation 的流向

## 2 场景：家庭视频检索

### 2.1 任务定义

- **输入**：摄像头 24/7 视频流，抽帧处理
- **VLM 任务**：帧描述 + 物体检测 + 文本索引
- **检索**：自然语言查询 → 向量检索 → 时间戳定位
- **隐私**：全部本地执行，数据不出设备

### 2.2 上下文规模

| 量 | 值 |
|---|---|
| 视频时长 | 100 小时 |
| 抽帧帧率 | 1 fps |
| 每帧编码 tokens | 64 |
| 总 tokens | **23,040,000** |

### 2.3 KV Cache 爆炸问题

标准 Attention 在 23M tokens 下的 KV Cache（7B, 32 层, FP16）：

| Attention 类型 | 单位 token 开销 | 23M tokens |
|---|---|---|
| MHA（32 heads） | 512 KB | 11.5 TB ❌ |
| GQA（4 heads） | 64 KB | 1.4 TB ❌ |
| MLA（rank=512） | 40 KB | 880 GB ❌ |

**结论：任何随序列增长的 KV cache 都不可行，必须常数级。**

## 3 为什么不用纯 Linear Attention

DeepSeek-V4 最终选择 MLA（Multi-head Latent Attention）而非纯 Linear Attention，原因如下：

### 3.1 训练不稳定（DMC 问题）

纯线性注意力在长序列训练中容易退化。状态矩阵 S 被历史信息累积淹没，最近的 token 反而被"稀释"。Softmax 天然有归一化，不存在这个问题。

### 3.2 检索精度差

线性注意力本质是"特征平均"，丢失了 token 级别的精确匹配能力。通用 LLM 必须保证 recall/retrieval 任务的精度（代码补全、实体匹配等）。线性注意力在这类任务上表现明显差于 softmax。

### 3.3 硬件生态不成熟

Linear attention 的核心操作是外积累积 `S += k^T v`，这是 D×D 的小矩阵逐步累积。现代 GPU 对 GEMM 优化极好，但对"小矩阵逐步累积"效率不高。FlashAttention 对 softmax attention 的优化已经非常成熟，linear attention 反而没有对应的高效 kernel。

### 3.4 DSv4 的选择：MLA

DSv4 选择 MLA 的路径是：
- **存的时候压缩**：KV 压缩到低秩潜空间（rank=512），KV cache 缩减到 MHA 的 ~10%
- **算的时候标准注意力**：查询时仍然用 softmax attention

这比线性注意力更可控，不会引入训练不稳定。

## 4 我们的方案：三分支混合注意力

### 4.1 核心思路

DSv4 的压缩机制是一个很好的**结构化前端**，把原始序列组织成有意义的时空层级。我们在此基础上：

- **CSA compressed entries** → **Linear attention**（不存 KV，只维护 O(d²) 累积矩阵）
- **HCA compressed entries** → **Linear attention**（同上，指数衰减累积）
- **SWA uncompressed tokens** → **标准 Softmax attention**（保局部精度）

三个分支通过**可学习门控**（softmax gate）加权融合，训练时自动学习最优权重。

### 4.2 三层金字塔结构

```
原始序列 (n tokens)
    │
    ├── CSA 压缩 (m=4, 重叠) → n/4 个 compressed entries
    │     功能：跨流注意力，decay=0.99
    │     KV cache: O(D²) 常数
    │
    ├── HCA 压缩 (m'=128, 不重叠) → n/128 个 compressed entries
    │     功能：场景级覆盖，decay=0.999（更慢衰减 = 更长记忆）
    │     KV cache: O(D²) 常数
    │
    └── SWA (窗口=128, 不压缩) → 保局部精度
          功能：标准 softmax 因果注意力 + RoPE
          KV cache: 128 × d × 2（常数）
```

### 4.3 各层语义

| 层 | 压缩比 | 输出数量 (23M tokens) | 语义层级 | 注意力类型 |
|---|---|---|---|---|
| HCA | 128:1 | ~180K | **场景级**：每 128 帧一个描述 | Linear attention, decay=0.999 |
| CSA | 4:1 | ~5.75M | **聚焦级**：最相关的细节 | Linear attention, decay=0.99 |
| SWA | 1:1 | 128 | **时间级**：最近 2 秒精确内容 | Softmax attention + RoPE |

### 4.4 两阶段检索管道

```
┌─────────────────────────────────────────────────────────┐
│ 阶段一：Ingestion（常驻运行，24/7）                       │
│                                                         │
│  视频流 → 抽帧 → Visual Encoder → CSA+HCA linear attn   │
│                                                         │
│  产出:                                                    │
│  - HCA 累积状态（O(c²) 常数） → 场景压缩摘要             │
│  - 帧级 embedding → 写磁盘时序索引（按需）                │
│  - CSA 的 decaying 状态 → 最近关注焦点                    │
│  - SWA → 最近 2s 精确内容 → 实时处理                     │
│                                                         │
│  内存: 常数 ✓  不需 eviction ✓  无限运行 ✓                │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│ 阶段二：Query（用户触发）                                  │
│                                                         │
│  用户: "冰箱门什么时候打开的？"                             │
│                                                         │
│  1. Query 文本 → 编码 → Text Queries                     │
│  2. 对磁盘索引做 Cross-Attention（标准 MultiheadAttn）    │
│  3. 返回相关帧 + 时间戳                                   │
│                                                         │
│  精确性: 全量 Softmax Attention 在索引上 ✓                │
│  内存: 索引在磁盘，只需要加载 Top-K 结果 ✓                │
└─────────────────────────────────────────────────────────┘
```

## 5 模型架构：EdgeTransformer

### 5.1 整体结构

```
输入 token ids: [B, T]
    │
    ├── Embedding(vocab_size, dim)
    ├── + 可学习位置编码 (1, max_seq_len, dim)
    │
    ├── HybridBlock × N（FP32：SWA + FFN 在 FP16 下梯度溢出）
    │   ├── LayerNorm
    │   ├── SeqCompress CSA (avg_pool, kernel=4, stride=2) → n/2
    │   ├── SeqCompress HCA (avg_pool, kernel=128, stride=128) → n/128
    │   ├── SWA window (最后 128 tokens)
    │   │
    │   ├── CSA (Linear Attention, FP32, decay=0.99) on n/2
    │   ├── HCA (Linear Attention, FP32, decay=0.999) on n/128
    │   ├── SWA (Softmax Attention + RoPE, FP32) on window
    │   │
    │   ├── SeqExpand (nearest 插值) CSA → n, HCA → n
    │   ├── 可学习门控 softmax(gate) 融合三分支
    │   ├── 残差连接
    │   ├── LayerNorm
    │   └── FFN (Linear → GELU → Linear, FP32)
    │
    ├── LayerNorm
    └── Linear LM Head (FP16，可与 Embedding 共享权重)
```

### 5.2 核心模块详解

#### RoPE（旋转位置编码）

```python
# 通过复数乘法实现相对位置编码
# 频率: 1 / (base^(2i/dim))，i=0,1,...,dim/2-1
# 应用: q, k 各自乘以旋转因子
freqs = t.unsqueeze(-1) @ inv_freq.unsqueeze(0)  # [T, D/2]
# 将实数对视为复数，复数乘法 = 旋转
```

#### Linear Attention（线性注意力）

```python
# 特征映射: relu(x)² + 0.1（替代 elu，避免 DirectML 兼容问题）
# 累积状态: S += k^T v（外积，D×D 矩阵）
# 归一化项: z += k
# 输出: q @ S / (q @ z)
# 复杂度: O(T × D²)，内存恒定 O(D²)
```

#### 三分支融合

```python
# CSA: Linear Attention, decay=0.99, 1 head
# HCA: Linear Attention, decay=0.999, 1 head
# SWA: Softmax Attention + RoPE, num_heads heads
# 门控: g = softmax(gate)，x = x + g[0]*csa + g[1]*hca + g[2]*swa
```

### 5.3 AMP 兼容性

HybridBlock 内部的 `scaled_dot_product_attention`（SWA）和 `GELU + Linear`（FFN）
在 AMP FP16 反向传播时梯度容易溢出（step 300 后一致 NaN）。解决方案：
- HybridBlock 整体在 `torch.amp.autocast('cuda', enabled=False)` 中运行 → FP32
- Embedding、LayerNorm、LM Head 仍受 AMP 调度，走 FP16
- 实测 8 层模型 AMP 下 830 tok/s vs FP32 下 590 tok/s（提速 1.4x）

### 5.4 默认配置

| 参数 | 值 | 说明 |
|---|---|---|
| vocab_size | 4096 | BPE 词表 |
| dim | 512 | 隐藏层维度 |
| num_layers | 4 | HybridBlock 层数 |
| num_heads | 8 | SWA 多头注意力头数 |
| head_dim | 64 | 每个头的维度 |
| ffn_mult | 4 | FFN 扩展倍数 |
| max_seq_len | 512 | 最大序列长度 |
| weight_tie | True | 共享 embedding 和 LM head 权重 |
| **总参数量** | **~16M** | |

## 6 训练流水线

### 6.1 文件结构

```
train/
├── config.py       # 数据类配置（Model/Data/Train/Run）
├── model.py        # EdgeTransformer 模型定义
├── data.py         # COCO 数据加载 + BPE tokenizer
├── train.py        # 训练主循环
├── utils.py        # LR 调度、Logger、Checkpoint
└── requirements.txt
```

### 6.2 训练特性

| 特性 | 说明 |
|---|---|---|
| 混合精度 | AMP（FP16 + FP32），HybridBlock 内跑 FP32（SWA softmax + FFN GELU 在 FP16 下梯度溢出） |
| 梯度累积 | 等效放大 batch size |
| 学习率调度 | 余弦退火 + 线性预热 |
| Checkpoint | best/last/定期保存，支持 resume |
| 日志 | JSON 格式，step/loss/ppl/lr |
| 权重初始化 | Linear: N(0, 0.02), Embedding: N(0, 0.02) |
| BPE 分词器 | 基于 HuggingFace tokenizers（Rust），训练/编码 100x 加速 |

### 6.3 使用方法

```bash
# 3060 上训练（默认配置）
python train.py

# 自定义配置
python train.py --dim 768 --num_layers 6 --num_heads 12 \
                --batch_size 16 --steps 20000 --seq_len 1024

# 恢复训练
python train.py --resume checkpoints/edge_transformer/last.pt

# 指定数据路径
python train.py --coco_zip /path/to/annotations_trainval2017.zip
```

### 6.4 训练结果（3060, AMP）

**4 层模型**（dim=512, 8 heads, ~16M params, batch=16, FP32）：

| Step | Train Loss | Train Ppl | Val Loss | Val Ppl | Speed |
|---|---|---|---|---|---|
| 0 | 8.40 | 4449 | - | - | - |
| 100 | 5.76 | 316 | - | - | 1650 tok/s |
| 200 | 5.04 | 155 | - | - | 1630 tok/s |
| 300 | 4.58 | 98 | - | - | 1635 tok/s |
| 400 | 4.49 | 89 | - | - | 1640 tok/s |
| 500 | 4.42 | 83 | 4.53 | 93 | 1645 tok/s |

**8 层模型·金字塔版**（dim=512, 8 heads, ~30M params, batch=16, AMP）：

| Step | Train Loss | Train Ppl | Val Loss | Val Ppl | Speed |
|---|---|---|---|---|---|
| 0 | 8.39 | 4407 | - | - | 3471 tok/s |
| 200 | 4.71 | 111 | - | - | 3858 tok/s |
| 500 | 3.56 | 35 | 3.73 | 42 | 4011 tok/s |
| 1000 | 2.71 | 15 | 3.73 | 42 | 4026 tok/s |

**说明**：
- 金字塔结构运行在压缩域：CSA n/2, HCA n/128, SWA 最后 128 tokens → 每个 block 只处理 388 个 token 而非 1536
- **速度提升 3.5x**（830 → 4000 tok/s），参数量不变（零参数 avg_pool 压缩器）
- 相同步数下 PPL 更低（金字塔版 15 vs 全量版 67 @ 720 步）——压缩域注意力更聚焦
- 训练/验证 gap 开始拉大（2.71 vs 3.73），8M COCO 数据对 30M 模型略不足

## 7 方案对比

| 维度 | 纯 Mamba | 纯 Linear Transformer | MLA (DSv4) | **本方案 (三分支)** |
|---|---|---|---|---|
| 长程检索 | ❌ SSM 丢失细节 | ❌ 特征平均 | ✅ 压缩 + softmax | ✅ Linear attn + 累积状态 |
| 局部精度 | ✅ 状态追踪 | ❌ 无局部窗口 | ✅ SWA | ✅ SWA |
| 常数内存 | ✅ | ✅ | ❌ O(L) 压缩后 | ✅ O(D²) |
| 可训练性 | ✅ 稳定 | ❌ DMC 问题 | ✅ 稳定 | ✅ softmax 保底 |
| 视频场景理解 | ⚠️ 帧独立 SSM | ⚠️ 模糊化 | ⚠️ 无结构感知 | ✅ 三层金字塔 |
| 硬件兼容性 | ✅ 纯 GEMM | ✅ 纯 GEMM | ✅ GEMM | ✅ GEMM + 外积 |

**本方案的独特价值：对视频场景的结构自觉性。**

## 8 已知问题与下一步

### 8.1 已解决

- [x] DirectML 在 K6000 上 element-wise add/mul 不可用 → 改用 CPU 训练
- [x] `elu` 在 DirectML 上 fallback → 改用 `relu² + 0.1` 特征映射
- [x] `scaled_dot_product_attention` 在 DirectML 上不支持 `triu` → SWA 仅在 CUDA 上使用
- [x] BPE tokenizer 训练完成，4096 vocab（HuggingFace tokenizers Rust 实现）
- [x] 训练流水线在 3060 上可运行，loss 正常下降
- [x] AMP NaN 问题：HybridBlock 内 SWA softmax + FFN GELU 在 FP16 下梯度溢出 → 整块跑 FP32
- [x] `linear_attn` 形状 bug：`squeeze(-1)` 误删特征维而不是序列维 → 改为 `squeeze(2)`
- [x] `linear_attn` FP16 溢出：`relu(x)²` 特征映射超 65504 → 累积矩阵 S 和整个循环跑 FP32
- [x] `apply_rope` ComplexHalf 警告 → 用实数运算替代复数乘法，兼容 FP16
- [x] **结构式对齐**：CSA 4:1 + HCA 128:1 金字塔压缩，SWA 128 窗口，SeqExpand 上采样融合
