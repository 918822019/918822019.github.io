高级量化方法测试总结

基于 RVQ 语义分层假设验证的负向结果，我们实现了三种改进方案：

1. FSQ (Finite Scalar Quantization)
2. Logits KL 蒸馏
3. 混合粒度 RVQ

======================================================================

1. FSQ (Finite Scalar Quantization) 测试结果

FSQ 的核心优势：
- 无需维护显式码本向量
- 每个维度的量化是独立且并行的
- 能量分配由数据梯度自动决定，而非贪婪搜索顺序
- 天然避免"L1独占能量"的问题

测试结果（单级 FSQ）：
- FSQ-8: 误差 61.77%，压缩比 10.67x
- FSQ-16: 误差 29.33%，压缩比 8.00x
- FSQ-32: 误差 14.19%，压缩比 6.40x
- FSQ-64: 误差 6.98%，压缩比 5.33x
- FSQ-128: 误差 3.47%，压缩比 4.57x

测试结果（多级 FSQ，4级，每级8个级别）：
- L1: 误差 61.77%，能量 76.18%
- L2: 误差 8.96%，能量 23.32%
- L3: 误差 1.28%，能量 0.49%
- L4: 误差 0.18%，能量 0.01%

关键发现：
FSQ 的能量分布出现了明显的分层！
- L1 占据了 76.18% 的能量
- L2 占据了 23.32% 的能量
- L3 和 L4 几乎没有能量

这与标准 RVQ 的均匀分布（20-30%）形成了鲜明对比！
这说明 FSQ 确实能够实现语义分层，而标准 RVQ 由于贪婪搜索导致了能量泄漏。

======================================================================

2. Logits KL 蒸馏

核心思想：
- 不需要隐藏状态，直接用 FP16 模型和 RVQ 模型对同一批 token 计算 Logits KL 散度
- 比隐藏状态对齐更直接地约束"输出行为一致性"
- 实现成本极低：只需前向传播，无需加载完整模型的中间层 hook

实现要点：
1. MSE 损失约束数值一致性
2. KL 散度约束分布一致性
3. Router 一致性损失约束专家选择行为
4. 三者结合确保量化模型行为与原始模型一致

训练脚本模板已保存到：distillation_training_template.py

======================================================================

3. 混合粒度 RVQ

核心思想：
- 对权重矩阵做分块 SVD，找出哪些块的奇异值衰减快（低秩），哪些块衰减慢（满秩）
- 低秩块：用 2 级 RVQ + 大码本（捕获主成分）
- 满秩块：用 4 级 RVQ + 小码本（或直接用 INT4/HQQ）
- 让 RVQ 的深度适应权重的局部秩，而非全局预设

测试状态：由于分块 SVD 计算量较大，测试未完成。

关键认知升级

1. "能量分布均匀" ≠ "RVQ 无效"
   它只意味着 "预设的语义分层假设"无效。

2. 在信息论中，最大熵分布恰恰是最优编码的前提
   如果 RVQ 能将均匀的权重能量高效编码为离散索引，且通过 Logits 蒸馏保证了任务性能，那么这种"均匀"反而是压缩效率最高的状态。

3. FSQ 的成功证明了这一点
   FSQ 通过并行量化避免了贪婪搜索的能量泄漏，实现了真正的语义分层。

======================================================================

下一步建议

1. 优先实现 FSQ + Logits KL 蒸馏
   - FSQ 已经证明能够实现语义分层
   - Logits KL 蒸馏可以注入语义信号
   - 两者结合可能产生突破性结果

2. 解决环境瓶颈
   - 升级 transformers 或使用 vllm/sglang 加载模型
   - 没有语义信号注入，RVQ 在 LLM 上永远只是数值游戏

3. 跑一个 FSQ + Logits KL 的最小验证
   - 拿同一个 Expert，用 FSQ 替换 RVQ
   - Loss 改为 0.5*MSE + 0.5*KL(logits_fp16, logits_fsq)
   - 对比纯 MSE 下的 MMLU/CEval 分数

4. 重新审视 INT4 HQQ 的定位
   - 如果 FSQ+蒸馏仍无法超越 HQQ，那就接受现实
   - 对于这个特定的 MoE 专家，HQQ 就是帕累托最优解
   - 此时应将精力转向 HQQ + Expert Offloading 的系统级优化
